## 1. 3C分析

### Customer（市場・顧客）
- YouTube 全年代83.3%・TikTok平均年齢39.2歳 — 大人向け演奏コンテンツでもショート3面が機能する（01参照）
- 評価アルゴリズムは3PF共通で「完走率・リピート・保存/シェア」。冒頭0〜3秒が生命線
- 視聴者は「曲」から入る（音源・検索導線）→「人」で残る（競合の勝ちパターン）
- 生成AI普及で「人間の生演奏」の相対価値が上昇

### Competitor（競合）
- 総合カバー型大手は頭打ち（ハラミちゃん+3万/17ヶ月）。伸びるのはポジションずらし組のみ
- 空白: アーティスト縦深掘り×解説／データ検証系／解説×ショート／大人初心者伴走（02参照）
- サカナクション曲は「単発カバー」は飽和、「専門深掘り」は不在

### Company（自社＝発信者）
- クラシック素養: 技巧・様式知識・譜読み力 → 「本物感」の担保、様式変換・解説ができる
- エンジニア×経営者: データ分析・自動化・仮説検証の習慣 → **演奏系で誰もやっていないデータドリブン運用**が可能。分析基盤を自作できる
- 制約: 可処分時間（代表業務との両立）、SNS実績ゼロからのスタート、動画編集の習熟

## 2. STP

### Segmentation（視聴者セグメント）

| セグメント | 規模感 | 入口 | 求めるもの |
|---|---|---|---|
| a. 原曲ファンダム | 曲次第で大 | 音源・ハッシュタグ検索 | 推しの新しい楽しみ方・解釈 |
| b. 音楽学習者（大人の再開組含む） | 中・高LTV | 検索（曲名+弾き方/楽譜/コード） | 弾けるようになる・理論がわかる |
| c. 作業用BGM層 | 大・低関与 | プレイリスト・長尺 | 邪魔しない心地よさ |
| d. ショート娯楽層 | 最大・非音楽 | アルゴリズム配信 | 2秒で伝わる驚き・ネタ |
| e. マーケ・ビジネス層 | 小・別文脈 | X/note/GitHub | 運用の学び・事例 |

### Targeting（順序が重要）
1. **初期（Phase 1）**: a＋d — トレンド曲×ショートで発見される（TikTokはフォロワー0でもバズが起こる構造）
2. **中期（Phase 2）**: b — 解説・講座要素で定着とLTV（検索資産化。ずっしー/かんたーんの型）
3. **並走**: e — 運用データの発信はX/noteで別レイヤー（本業シナジー。演奏アカウントとは分離）

### Positioning
**「クラシックの文法でネットの音楽を読み解く、データで動くピアノ研究室」**

- 競合との差別化軸: 「上手さ」でも「キャラの濃さ」でもなく、**解釈と検証**（なぜこの曲は中毒性があるのか、を弾いて示す）
- ポジショニングマップ上の狙い: 右上「技巧×専門特化」の空白（02参照）

## 3. SWOT → クロスSWOT

| | 内部: Strength | 内部: Weakness |
|---|---|---|
| | S1 クラシック素養（様式・技巧・譜読み） | W1 知名度ゼロ・実績ゼロ |
| | S2 データ分析・自動化スキル | W2 稼働が限られる（代表業務） |
| | S3 経営者の継続力・戦略思考 | W3 ショート動画文法・編集の未習熟 |
| | S4 BASHAKA/HOJORINの事業資産 | W4 顔出し未定＝人格軸が立ち上げにくい |

| 外部: Opportunity | 外部: Threat |
|---|---|
| O1 夜の踊り子ミーム進行中＋サカナクション8〜10月イベント密集 | T1 総合カバー型は大手飽和 |
| O2 演奏系にデータ検証系・アーティスト深掘りの空白 | T2 アルゴリズム変動・トレンド消費の速さ |
| O3 縦型動画広告+55.9%成長・バイラル賞新設の追い風 | T3 権利制度の変更リスク（包括契約の変動） |
| O4 生成AI時代の「生演奏」価値上昇 | T4 ストリートピアノ逆風（撤去・炎上） |

**クロスSWOT（採る戦略）**
- **S1×O1**: 夜の踊り子・怪獣を「クラシックの文法で解説しながら弾く」→ 単発カバー飽和（T1）を回避しつつ旬に乗る
- **S2×O2**: 全投稿を仮説検証として設計し、データごと公開する「build in public」→ 唯一性と本業シナジー
- **S3×T2**: トレンド追いに依存しない「検索資産型（解説・講座）」を並走させ、アルゴリズム変動を緩和
- **W2×T2**: 週2本に本数を絞り「型」を反復（遠坂めぐの勝因）。撮影→編集のテンプレ化で1本あたり工数を圧縮
- **W4対策**: 手元＋声から開始し、数値を見て段階的に露出を判断（6章）

## 4. コンセプト候補3案

> Phase 1（8〜10月）で3案を同一アカウント内の「ピラー」としてABテストし、データで主軸を決める。詳細な企画は [05_コンテンツ企画.md](./05_コンテンツ企画.md)。

### 案A 「サカナクション研究室」— アーティスト縦深掘り型
- 一言: **サカナクションを弾いて・分解して・語る専門ピラー**
- 根拠: 専門チャンネル不在の空白（02）× 8〜10月のイベント密集（03）× 夜の踊り子はピアノリフが主役
- 初動: 夜の踊り子リフカバー → 「なぜ中毒性があるのか60秒」→ 怪獣ライブアレンジ再現 → いらないPiano ver.研究（9/2週）→ ツアーセトリ予習メドレー
- リスク: 単一アーティスト依存・ファンダム外への広がり不足 → 「研究室」フォーマット自体は他アーティストへ拡張可能に設計
- 権利メモ: 楽曲ごとにJ-WID/NexTone確認を投稿チェックリストに組込（01の4章）

### 案B 「ピアノ×データラボ」— エンジニア経営者のbuild in public型
- 一言: **IT社長がピアノSNSをデータドリブンで攻略する過程を全公開**
- 根拠: 検証・データ系演奏コンテンツの不在（02の空白9）× S2の直接活用 × 戦略をGitHubで管理していること自体が一次コンテンツ
- 初動: 「同じ曲を投稿時間だけ変えて出したら」「保存率が高い曲の共通点」「電子ピアノ3台弾き比べ」＋月次の数値公開
- リスク: 刺さる層がマーケ・エンジニア寄りで演奏ファンと混ざる → 演奏はYT/TikTok、データ語りはX/noteに分離して両取り
- 副次効果: BASHAKA/HOJORINの「データで運用する会社」という実績デモ（本業シナジー）

### 案C 「クラシック翻訳機」— 様式変換×60秒解説型
- 一言: **「もしショパンが好きすぎて滅！を弾いたら」— ミーム曲をクラシック様式に翻訳**
- 根拠: クラシック素養の直接活用（S1）× 解説×ショートの空白（02の空白5）× トレンド曲を「単発カバーにしない」出し方（T1回避）
- 初動: 夜の踊り子×ラヴェル風 → バッハ様式でBEAUTIFUL MOON FUNK → 「ラ・カンパネラがバズる理由60秒」
- リスク: 企画1本あたりのアレンジ工数が重い → 月2本の「大ネタ」枠として運用し、通常投稿と分ける

### 推奨構成
- **1アカウント3ピラー**でスタート（アカウント分割はしない。ジャンル一貫性は「ピアノ×解釈」で担保）
- **8月中旬〜9月は案Aを前倒し**（サマソニ→9/2シングル→ツアーの時流。03参照）
- 判定は感覚ではなく**保存率・完走率・フォロワー転換率**で行う（→ [06_KPI・運用.md](./06_KPI・運用.md)）

## 8. 本業シナジーの設計（副次ゴール）

- 演奏アカウントに社名を前面に出さない（コンテンツ純度優先）。プロフィールに一行接点のみ
- データ運用の知見はX/note/GitHubで「BASHAKA代表」名義で発信 → 採用・営業の信頼材料
- HOJORINセールス/ワーカーの「SNS運用をデータで回す」事例として社内ナレッジ化（このリポジトリ自体が成果物）
