## 1. ペルソナ — チャンネルはここから逆算する

テーマは「ジャンル」からではなく**ペルソナ（誰が見るか）から逆算する**。

| | ① ユウ → `meme` | ② サトシ → `trivia` | ③ アヤ → `heisei` |
|---|---|---|---|
| 像 | 24歳・若手。ニコニコ文化圏育ち | 42歳・地方の会社員・既婚 | 35歳・平成小学生世代の会社員 |
| 動機 | **ネタと文脈**を消費したい | 強い悩みはない。「へぇ」と少しの得 | 「あったあった！」と語りたい |
| SNS行動 | YouTube・X・ニコニコ。**コメント欄で大喜利** | YouTubeのみ。完走するがコメント・保存はしない | IG・YouTube。**コメントで思い出を語る** |
| 刺さる型 | キャラ掛け合いの妙・元ネタの文脈 | 30秒で「へぇ＋ちょっと得」 | 共感の懐古＋「そういえばアレどうなった？」 |
| ファン化 | **最速（キャラのファンになる）** | 低（母数で勝負） | 中（コメント常連化） |

旧ペルソナのミサキ（girls）・ケンタ（biz）はv6で、タクヤ（f1）はv6.1で退場。
**サトシは trivia の主ペルソナに昇格**したが、「どの台本もサトシが見て30秒で分かるか」
という全チャンネル共通の**分かりやすさの下限**チェックとしての役割は続ける。

## 2. 台本の型 — キャラ掛け合いの5シーン

5シーン構成は維持する（型の固定は視聴者の学習を促す。[02](./02_競合分析.md) 1章）。
**中身がナレーションから2キャラの会話に変わる。**

**v5以降、0からの創作はしない。** `meme` / `heisei` は採用スレ（`data/threads/`・
目視選別済み）の翻案、`trivia` / `heisei` は裏取り済みの事実が入力になる。
台本は**オチから逆算する**: まず一番面白い点（スレのオチ／事実の意外さ／ニュースの
引っかかり）を一文で特定してシーン5に置き、シーン1のフックは「オチへの期待」を作る。
オチを一文で言えないネタは、そもそも採用しない（3章）。
会話のラリーは詰める。説明口調の分担読みは禁止（ドーパミン設計。[04](./04_戦略.md) 2-2章）。

| # | 役割 | 中身 | 秒数の目安 |
|---|---|---|---|
| 1 | **フック** | 3秒以内に「何の話か」。片方の悲鳴・疑問で入る | 3〜5秒 |
| 2 | 本編① | あるある・状況の再現（掛け合い） | 5〜8秒 |
| 3 | 本編② | 核心・理由 | 5〜8秒 |
| 4 | 本編③ | チャンネル別の本体（下記） | 5〜8秒 |
| 5 | 締め | 持ち帰れる一言＋問いかけ | 3〜5秒 |

### チャンネル別の型

| ch | 型 | シーン4に入るもの | 配役 |
|---|---|---|---|
| `meme` | **スレ引用 → 寸劇・ツッコミ → パワーワードで終わる** | オチの直前の展開（スレの転換点） | ずんだもん（ボケ）×めたん（ツッコミ・解説） |
| `heisei` | **「◯◯選」リスト**（主）／「あれ覚えてる？」掛け合い（従） | リストは各ネタを16字で投げる。掛け合いは当時の実像 | めたん（懐かしむ先輩）×ずんだもん（平成を知らない後輩） |
| `trivia` | **「実は◯◯」フック → 意外な事実 → 根拠（一次ソース） → もう一段の意外** | 根拠。「どこ情報？」に答える出典 | ずんだもん（驚く役・視聴者代弁）×めたん（種明かし役） |

### 掛け合いを平坦にしない（全チャンネル共通・2026-08-03）

生成物313行を分析したら、**ずんだもんの94%が「〜のだ」で終わり、中身は
「ないのだ」「しいのだ」など形容詞1語の相槌**だった。2人のセリフ長もほぼ同じで、
説明文の分担読みになっていた（本人評価「スムーズすぎて人間らしさがない」）。

| ルール | 中身 |
|---|---|
| **一問一答にしない** | 「情報→質問→回答」の繰り返しはQ&Aであって会話ではない。**質問は1本に最大2回** |
| **2人に意見を持たせる** | 各シーンに最低1つ、立場を表明する行（「ボクなら」「〜と思う」「あなたは〜でしょ」）。**1本に1回は意見が食い違う場面**を作る |
| **相槌を書かない** | 感想だけで終わる行を1行も入れない。口を開くなら疑問・たとえ・自分の話・反論・飛躍を足す |
| **語尾を連続させない** | 同じ語尾を2行以上続けない。疑問形・体言止め・言い切り・途中で切るを混ぜる |
| **役割を非対称に** | 情報を持つ側は25〜35字で数字と固有名詞を出す。聞き役は5〜20字で食い気味に差し込む |
| **スムーズに進めない** | 被せる・見当違い・脱線して戻る・納得しないを1本に最低2回 |
| **感心して終わらない** | 「勉強になった」で終わると何も残らない。引っかかりか笑いか次の疑問を残す |

`script.py` の `dialogue_issues()` が生成後に自動チェックし、
相槌・語尾の連続・**質問過多（40%超）**・**意見表明の不足**・字数の非対称性の欠如を
警告する（止めはしない）。

> 「疑問形を増やす」だけを指示すると質問だらけになって一問一答に陥る。
> **足すべきは質問ではなく意見**（2026-08-03の失敗）。

### `meme` は掲示板の記号を捨てる

登録者51.2万のチャンネルはタイトルに `www` を0%・`【悲報】` を0%しか使っていない。
逆にそれらを使う従来型は直近2,000〜3,000回まで落ちている（[02](./02_競合分析.md) 2章）。

- `www` `【悲報】` `ンゴ` などのなんJ語を caption に使わない。レス番号・ID・名前欄も出さない
- caption は **`【4〜6字の名詞句】`＋言い切る短文**（【ルールの盲点】【妙な説得力】…）
- **オチは「コメントで復唱できるパワーワード1個」に集約し、説明を足さずに終わる**
- 尺は26秒前後。セリフ12行・合計150字以内

### `trivia` は「どこ情報？」に必ず答える

雑学は間違えた瞬間にコメント欄で刺されて信用が飛ぶ。**一次ソースの裏取りが無い
ネタは台本にしない**（[#103](https://github.com/bashaka-sawabe/personal-sns-operation/issues/103) で機械的に強制）。
シーン4で出典に軽く触れる（「◯◯省の資料に載ってる話なのだ」程度。読み上げない）。

### `heisei` は「知らない後輩に説明する」構図で懐古を外に開く

懐古だけだと同世代にしか刺さらない。ずんだもん（平成を知らない）に説明する形にすると、
若い視聴者にも「そんな時代があったのか」で成立する。

フックは trivia と正反対で、**「あれ、覚えてる？」型**（知らない話の種明かしではなく、
知っている話の掘り起こし）。締めは「今どうなったか」か「当時は当たり前だった」の落差。
**年代・製品名は裏取り済みのものだけを言う**（世代ネタの誤りはコメント欄で一発で刺される）。
懐かしむ対象を馬鹿にしない・特定企業を貶さない。

**主力は「◯◯選」のリスト形式**（`--facts` に複数指定）。実測で
1本1ネタの情報提示型は185本出して1,000〜3,000回、リスト形式は登録者1.12万で21万回
（[02](./02_競合分析.md) 4章）。

- タイトルは「◯◯年生まれ**位**が懐かしい△△○選」。**「位」を必ず入れる**（前後10年を取り込む）
- 各ネタのセリフは**16字以内**。解説を入れない
- リストは全部を網羅しない。**入りきらないものを残す**のが正解
  （視聴者が「◯◯が無い」と補完コメントを打つ余地。コメントの正体は
  「年齢の名乗り」と「リストの穴埋め」の2つ）

## 3. ネタ選びの基準

**全チャンネル共通:**

1. **オチ（一番面白い点）を一文で言えるネタだけ採用する**
2. 15〜45秒で語り切れる（1本1ネタ・1オチ）
3. 実在人物の誹謗中傷・個人特定・他クリエイター批評はしない（[02](./02_競合分析.md) 7章）
4. **採用は必ず人の目視で決める**
5. ペルソナの顔で選ぶ。「この人がこれを最後まで見るか？」

**チャンネル別:**

| ch | 基準 |
|---|---|
| `meme` | 引用元は**転載自由ソースのみ**（[04](./04_戦略.md) 2-2章）。**「コメントで復唱できるパワーワードが1個作れるか」がスレ選定の第一基準**（[02](./02_競合分析.md) 2章）。収集は `tools/fetch_threads.py` |
| `heisei` | **事実ベースが主**（`tools/fetch_facts.py --channel heisei`。年代・製品名は裏取り必須）。懐かしスレは出現頻度が低く旬に依存するため、スレ待ちにしない（[#113](https://github.com/bashaka-sawabe/personal-sns-operation/issues/113)）。良いスレが出た日は `--thread` の引用型でも作れる。**懐かしむ対象を馬鹿にしない・特定企業を貶さない** |
| `trivia` | **一次ソースで裏取りできた事実のみ**（`tools/fetch_facts.py` が裏取り無しの採用を拒否する）。裏取りの優先順位: **官公庁・政府統計・学術機関 > 信頼できる一次報道 > Wikipedia経由で原典にたどる**。「信じられないが本当」の落差が大きいものを優先。医療・投資の助言に踏み込まない |

### `girls` — ミサキ向け・主戦場候補

| テーマ | 狙い | 持ち帰る一言の種 |
|---|---|---|
| 飲み会の上手な断り方 | 実用性が高く保存されやすい | 先に次を約束する |
| 既読スルーされたときの考え方 | 母数最大の悩み。共感の入口 | 返信は相手のタイミングの問題 |
| 同期と比べて落ち込む夜の抜け出し方 | 「自分だけじゃない」で共感 | 比べる相手を昨日の自分にする |
| 「いい人止まり」で終わる人の共通点 | 恋愛文脈。タイトルで押せる | 好意は小出しに見せていい |

### `biz` — ケンタ向け・信用の土台

| テーマ | 狙い | 一次情報の置き所 |
|---|---|---|
| 法人化で税金は減るのか | 起業検討層に刺さる本命 | **法人化して実際に変わったこと・想定外だったこと** |
| 手取りが少ない本当の理由 | 会社員にも刺さる（会社負担の社保） | 保険料・税金の引かれ方で実際に誤算だったこと |
| 独立1年目に踏む落とし穴 | 「先に知りたかった」の典型 | 実際に踏んだ手順・失敗 |
| 角を立てない仕事の断り方 | 経営者は断る回数が多い | 実際に使っている言い回し |

### `meme` — ユウ向け・拡散力とキャラ人気のテスト

| テーマ | 狙い |
|---|---|
| 猫ミームの元ネタ、全部知ってる？ | ど真ん中の題材。検索も効く |
| OIIA（回転猫）はなぜ2億回再生されたのか | 数字フックで非ミーム層にも届く |
| インターネット老人会: Flash黄金時代 | 懐かしさはコメントが伸びる |
| Xあるある寸劇 | キャラの演技力＝掛け合いの質のテスト |

## 6. 投稿前チェックリスト（毎回・全項目）

### 内容

- [ ] シーン1が**3秒以内**に「何の話か」を言い切っている
- [ ] 1本1ネタ・1オチになっている
- [ ] **サトシが見て30秒で分かる**（専門用語を裸で使っていない）
- [ ] オチのあとに蛇足（解説・まとめ）が付いていない

### 事実

- [ ] `trivia`: **一次ソースのURLが台本に記録されている**。制度・数字は「2026年時点」と分かる書き方で断定しない
- [ ] `heisei`: 年代・名称の事実関係を確認した（世代ネタの誤りはコメント欄で一発で刺される）
- [ ] `meme`: 元ネタの出典を確認した（誤った元ネタ紹介はこの層に一発で見抜かれる）
- [ ] 医療・投資・税務の助言に踏み込んでいない（[01](./01_市場分析.md) 6章）

### 表示・規約

- [ ] **クレジット表記**がある: `VOICEVOX:ずんだもん` `VOICEVOX:四国めたん`＋立ち絵素材の作者（[08](./08_自動化.md)）
- [ ] TikTokで**AI生成ラベル**を付けた（合成音声を使っている間は必須。[01](./01_市場分析.md) 4章）
- [ ] 説明文に合成音声を使っている旨を書いた
- [ ] 他クリエイターの批評・専門家を貶める煽りが入っていない（[02](./02_競合分析.md) 7章）
- [ ] 会社名・サービス名を出していない（**素材規約上も要許諾**。[08](./08_自動化.md)）
- [ ] `meme` / `heisei`: 引用元スレが**転載自由ソース**である（[04](./04_戦略.md) 2-2章）
- [ ] `heisei`: 当時のCM・番組映像・商品パッケージ・キャラ絵を使っていない

> **事実確認は飛ばさない。** お金の話で数字を間違えると、その1本が滑るだけでなく
> チャンネルの信用ごと飛ぶ。台本はAIが書くが、**確認は人がやる**。

## 7. ネタの補充

週次レビュー（[06](./06_KPI・運用.md) 4章）で回す。

| 補充元 | 拾い方 |
|---|---|
| **掲示板スレ（meme / heisei の主ルート）** | `tools/fetch_threads.py` で候補を集め、**目視で採用を決める**（3章の基準） |

| Threadsの反応 | テキストで先に出して、伸びたものを動画化する（[04](./04_戦略.md) 5章） |

## 8. 主戦場確定後（Phase 2）

判定（[#19](https://github.com/bashaka-sawabe/personal-sns-operation/issues/19)）で勝ちチャンネルが決まったら:

1. 負けチャンネルは**休止**する（削除しない。検索の長尾は残る）
2. 勝ちチャンネルの深掘りテーマを30本作る
3. 台本の型（2章）をそのチャンネルに合わせて調整する（[09](./09_パイプライン.md) の `SYSTEM`）
4. **本人の共演（Phase 2の橋）**の演出を設計する（[04](./04_戦略.md) 7章）
