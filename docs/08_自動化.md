# 08. 自動化方針とセットアップ

> 最終更新: 2026-07-27 ／ 前提: [06_KPI・運用.md](./06_KPI・運用.md)（計測項目）、[01_市場分析.md](./01_市場分析.md)（PF仕様と規制）
> 動画生成・投稿の実装は [09_パイプライン.md](./09_パイプライン.md)。

## 1. 方針 — 何を自動化し、何を自動化しないか

| レイヤー | 自動化 | 理由 |
|---|---|---|
| 台本の下書き | **する** | Claude APIで生成。3チャンネルを同じ型で回せる |
| 映像・音声の生成 | **する** | 1本68秒。2週間でジャンル判定を終えるための回転数 |
| 投稿 | **する（PF次第・3章）** | 4面に同じ12本を出す。手作業だと出し忘れる |
| 計測・記録 | **する（最優先）** | ジャンル別集計が判定の本体。ここが止まると判定できない |
| **ネタの採用（候補→adopted）** | **原則しない（委任は可・下記）** | どれが面白いかの目利きがAI量産スロップ対策の本体 |
| **事実確認** | **しない** | AIが書いた数字をAIが検証しても意味がない。**人がやる** |
| **一次情報の掘り起こし** | **しない** | 「自分がいくら払ったか」は本人しか出せない。**ここが価値の源泉** |
| **投稿直後のコメント返信** | **しない** | 2章 |
| フォロー・いいね・DM | **絶対にしない** | 2章。規約違反 |

### ネタ採用の委任（2026-08-07 本人決定）

採用は原則本人の目視だが、**本人がその都度明示的に委任した場合**は Claude が
選定〜採用まで行ってよい。条件:

- 委任は都度（「選定も任せる」等の明示）。**常設の自動採用にはしない**
- fact系は**一次ソースの裏取り（backing_url）を必ず付けてから**採用する
- 何をなぜ採用したかを報告し、本人はいつでも `--reject` で覆せる

### 自動化の目的を間違えない

浮いた時間を**制作の本数**に使うのではなく、**事実確認と一次情報**に使う。

本数だけ増やすと、[01](./01_市場分析.md) 4章の規制に真正面からぶつかる。
**パイプラインは勝ち筋ではなく、テストの回転数を上げる道具**（[04](./04_戦略.md) 2章）。

## 2. やってはいけない自動化

**自動フォロー／自動いいね／自動DM／フォロワー・再生数の購入は3PFすべてで規約違反。**
シャドウバン・アカウント凍結の対象であり、加えて**Phase 1の検証データが汚染される**
（数値が実力を反映しなくなり、ジャンル判定＝Phase 1の最重要目標が不能になる）。

「SNS自動化ツール」として流通しているものの多くがこれに該当する。
導入前に必ず「何を自動でやるツールか」を確認する。

**投稿直後30〜60分のコメント返信は手動で行う。**
ここは自動化しないほうがアルゴリズム上も有利で、かつ
**コメント率＝人格への移行の芽**（[06](./06_KPI・運用.md) 1章）を育てる場所そのもの。

### AI生成の表示は隠さない

TikTokは**自己申告しなくても C2PA・電子透かし・検知モデルで判定**する（[01](./01_市場分析.md) 4章）。
隠すと検知され、配信が絞られる。**合成音声を使っている間は必ずラベルを付ける。**

### キャラ素材の規約線引き（v4・2026-07-30 一次ソース確認済み）

ずんだもん・四国めたんは借り物のキャラであり、**規約が運用の上限を決める**。

**音声（VOICEVOX音源）** — [東北ずん子 音源利用規約](https://zunko.jp/con_ongen_kiyaku.html)

- 個人・法人の区別なく**商用利用可**。ただし**クレジット表記が必須**:
  `VOICEVOX:ずんだもん` `VOICEVOX:四国めたん`（動画説明欄などユーザーが見つけやすい場所）
- クレジット無しの商用利用は1キャラ40万円の契約になる。**表記を絶対に落とさない**
  （credits.txt と説明文への挿入はパイプラインで自動化する。[#56](https://github.com/bashaka-sawabe/personal-sns-operation/issues/56)）
- 禁止事項に「**意図的な虚偽・フェイク情報**」がある。事実確認（1章）は規約遵守でもある

**キャラクター・立ち絵** — [東北ずん子 キャラクター利用ガイドライン](https://zunko.jp/guideline.html)

- **個人クリエイター**: 動画投稿の広告収益は非商用範囲として扱われる。
  ただし**スポンサー案件・企業案件は有償利用となり要相談**
- **法人**（東北6県以外）: **別途ライセンス契約が必要**
- → **運用は個人名義で行う。** BASHAKA名義・会社サイトからの導線・案件受けをする場合は
  **事前に許諾を取る**。Phase 2の種明かし（会社名との接続）の前に必ず再確認する
- 立ち絵はファン制作素材（坂本アヒル氏等）を使う場合、**素材ごとの規約**に従い
  credits.txt に作者名を記載する

**青山龍星は使わない**（2026-08-06 本人決定・[#160](https://github.com/bashaka-sawabe/personal-sns-operation/issues/160)）。
音声規約に「企業・**個人事業主**・企業と契約した個人は、収益の有無にかかわらず
『ななはぴ』への**事前申請**が必要」という特別条項がある（一次ソース確認済み）。
名義を個人から切り替えた瞬間に申請漏れになるため、最初から使わない。
VirVoxの他キャラ（玄野武宏・白上虎太郎・冥鳴ひまり）にこの条項は無く、クレジットのみで商用可。
昭和の熱血役は玄野武宏のツンギレ（スタイル40）で代替する。

## 3. プラットフォーム別の自動化可否

| PF | 自動投稿 | 自動計測 | 制約 |
|---|---|---|---|
| **YouTube Shorts** | ○ **実装済** | ○ **実装済**（完走率は要再認可） | YouTube Data API。**クォータ1日10,000／アップロード1,600 = 1日6本が上限** |
| **Threads** | 未実装 | ○ 実装済 | Threads API。4面で最もハードルが低い |
| **Instagram** | 未実装 | ○ 実装済 | **プロアカウント必須**。動画は**公開URLにホストが必要**。API経由のReelsは5〜90秒。24時間100投稿まで |
| **TikTok** | **✗ 自前は不可** | ✗ | Content Posting APIは審査必須。**未審査だと投稿が `SELF_ONLY`（本人しか見えない）＋アカウント非公開が強制**され、サーバー側で強制されるため回避不可 |

### TikTokの運用

**審査済みのTikTok Marketing Partner（Buffer / Later / Metricool / Postiz 等）経由**にする。
自前で審査を通すのは、テスト期の投資として割に合わない。

数値は各投稿のアナリティクスから週次CSVに手入力する。
TikTokは0フォロワーでもバズり得る発見エンジンなので、手動コストを払う価値がある
（[#32](https://github.com/bashaka-sawabe/personal-sns-operation/issues/32)）。

### YouTubeのクォータ

**12本を1日で上げられない。** 2日に分ける。
`--all` は投稿済みを飛ばすので、翌日そのまま再実行すればよい。

## 4. 計測の自動化

### 4-1. 何ができるか

```bash
.venv/bin/python tools/fetch_metrics.py       # 数字を取得 → data/YYYY-Www.csv を作成・更新
.venv/bin/python tools/fetch_metrics.py --no-youtube   # YouTubeを飛ばす
.venv/bin/python tools/youtube_metrics.py     # YouTubeだけ確認する
.venv/bin/python tools/weekly_report.py       # 週次CSV → レビュー用Markdownを生成
.venv/bin/python tools/weekly_report.py --issue 10   # レポートを週次レビューIssueにコメント
```

- **チャンネル別（`girls` / `biz` / `meme`）に集計する。** 判定はこの比較そのもの
  （実装は旧ジャンル `money` / `relationship` / `trivia` のまま。[#56](https://github.com/bashaka-sawabe/personal-sns-operation/issues/56) 系の改修で追随する）
- YouTubeの `genre` は**投稿台帳から自動で入る**（`.published_youtube.json` → 台本JSON）。
  手入力に頼ると、埋まらないまま判定日が来る
- 手入力列（`issue_no` / `hypothesis` / `result_note` 等）は**APIの値で上書きされない**
- `views_48h`（初速）は**投稿から48時間以内に実行したときだけ**記録され、以後は上書きしない
- 1つのPFが落ちても他のPFの取得は続く

### YouTubeで取れるもの・取れないもの

| 指標 | どこから | 必要なスコープ |
|---|---|---|
| 再生・いいね・コメント | Data API `videos.list` | `youtube`（取得済み） |
| **完走率（平均視聴率）** | **Analytics API** | **`yt-analytics.readonly`（要再認可）** |
| **登録者増（動画単位）** | **Analytics API** | 同上 |

完走率を取るには一度だけ再認可が要る:

```bash
.venv/bin/python tools/publish_youtube.py --auth
```

**再認可しなくても、保存率・コメント率によるジャンル判定は成立する。**
完走率が無いと「作りの問題かジャンルの問題か」の切り分けができないだけ（[06](./06_KPI・運用.md) 2章）。

### プロフィールアクセス率（顔出し判断の分母）

PFで中身が違う。定義は [07](./07_ロードマップ.md) Phase 3。

| PF | 使う数字 |
|---|---|
| YouTube | 動画単位の登録者増（`subscribersGained`）。**「プロフィールアクセス」metricが無いため** |
| Instagram | media単位の `profile_visits` |
| TikTok | 手入力 |

**PFをまたいで足した絶対値には意味が薄い。** 見るのは同じPF内でのジャンル間の差と、
同じジャンルの週次推移。

### 4-2. トークンの準備（初回のみ）

[Meta for Developers](https://developers.facebook.com/) でアプリを1つ作り、両方のAPIを追加するのが早い。
取得した**長期トークン**を `~/repo/.cowork-secrets/` に置く（**コミットしないこと**）。

**Threads**（[Threads API](https://developers.facebook.com/docs/threads)）

1. アプリに「Threads API」ユースケースを追加し、`threads_basic` と `threads_manage_insights` を許可
2. 自分のThreadsアカウントを連携して短期トークンを取得
3. 長期トークン（60日）に交換:
   `GET https://graph.threads.net/access_token?grant_type=th_exchange_token&client_secret=<秘密鍵>&access_token=<短期トークン>`
4. `~/repo/.cowork-secrets/threads_token.txt` に保存

**Instagram**（[Instagram Platform](https://developers.facebook.com/docs/instagram-platform)）

1. **Instagramをプロアカウント（ビジネスまたはクリエイター）に切り替える**（未切替だとAPIが一切使えない）
2. アプリに「Instagram」プロダクトを追加し、Business Login for Instagram を設定。
   `instagram_business_basic` と `instagram_business_manage_insights` を許可
3. 長期トークンに交換:
   `GET https://graph.instagram.com/access_token?grant_type=ig_exchange_token&client_secret=<秘密鍵>&access_token=<短期トークン>`
4. `~/repo/.cowork-secrets/ig_token.txt` に保存（ユーザーIDを明示する場合は `ig_user_id.txt` も）

**YouTube**: OAuthクライアントの取得手順は [09_パイプライン.md](./09_パイプライン.md) 3章。

### 4-3. トークンの失効対策（重要）

Meta系の長期トークンは**60日で失効する**。放置すると自動計測が静かに止まる:

```bash
.venv/bin/python tools/fetch_metrics.py --refresh-token
```

YouTubeのリフレッシュトークンは、OAuthアプリの公開ステータスが「テスト中」だと
**7日で失効する**。「本番環境」に切り替えれば無期限（[09](./09_パイプライン.md) 3章）。

### 4-4. 定期実行

```cron
# 毎週日曜19:50 に計測（週次レビューの直前）
50 19 * * 0 cd ~/repo/personal/personal-sns-operation && .venv/bin/python tools/fetch_metrics.py >> /tmp/sns_metrics.log 2>&1
# 毎月1日にトークン延長（60日失効対策）
0 9 1 * * cd ~/repo/personal/personal-sns-operation && .venv/bin/python tools/fetch_metrics.py --refresh-token >> /tmp/sns_metrics.log 2>&1
```

初速（48時間以内）を取りこぼしたくない場合は日次にしてもよい（`0 21 * * *`）。

## 5. シークレットの置き場

`~/repo/.cowork-secrets/` に置く（**コミットしないこと**）。

`~/dev/` → `~/repo/` の移動実績があるため、コードは複数候補を順に探すようにしてある。
**1箇所決め打ちだと、トークンを置いても見つからず静かに壊れる**（実際に壊れていた）。

| ファイル | 用途 |
|---|---|
| `anthropic_key.txt` | 台本生成 |
| `youtube_client_secret.json` / `youtube_token.json` | YouTube投稿 |
| `threads_token.txt` | Threads |
| `ig_token.txt` / `ig_user_id.txt` | Instagram |
| `gh_token_personal.txt` | GitHub Issueコメント |

## 7. このドキュメントの更新ルール

- PFのAPI仕様は頻繁に変わる（特にMetaのmetric名）。**計測が壊れたら3章の表とスクリプトを更新してコミットする**
- `tools/fetch_metrics.py` はmetric取得に自動フォールバックを入れてあり、
  一部metricが廃止されても取れる分だけ記録して動き続ける。
  ただし**列が空になり続けている場合は仕様変更を疑う**
- **PFのAIポリシーは動きが速い。** 変更があったら [01](./01_市場分析.md) 4章と
  [03](./03_トレンド調査.md) 2章を同時に更新する
