# 09. 動画生成パイプライン

> 最終更新: 2026-07-27 ／ 前提: [08_自動化.md](./08_自動化.md)（自動化の線引き）、[06_KPI・運用.md](./06_KPI・運用.md)（判定指標）

## 1. これは何か

**AI生成映像＋ナレーション**の縦動画を、企画1行から自動で作るパイプライン。
キャラクターは置かず、映像とナレーションだけで構成する。

```
ジャンル × テーマ（1行）
        ↓ Claude API（claude-opus-5 / JSON強制）
台本JSON（フック＋本編3点＋締めの5シーン）
        ↓ Pexels API（image_prompt→検索語）／VOICEVOX（フレーズ単位で合成）
ストック映像＋ナレーション音声
        ↓ ffmpeg（フレーズ同期字幕・キーワード強調・BGMダッキング・連結）
content/out/<id>.mp4  （1080×1920 / 30fps / H.264+AAC）
```

外部素材が無くても止まらない。背景は **Pexels映像（キーがあれば）→ Openverse写真
（キーレス）→ グラデーション** の順で、音声は **VOICEVOX → macOS `say`** の順で
自動フォールバックする（グラデ・`say` まで落ちた品質で**投稿はしない**）。

## 2. 使い方

### 2-1. 生成

```bash
# 1本作る
.venv/bin/python tools/make_video.py --genre money --theme "経費で落ちるのに9割が申告してないもの"

# APIキー無しで疎通確認（テンプレ台本＋ローカル素材で最後まで通る）
.venv/bin/python tools/make_video.py --genre money --theme "テスト" --offline

# 2週間テストの本体。3ジャンル12本をまとめて生成する
.venv/bin/python tools/make_video.py --batch data/themes.md

# 台本だけ先に作り、中身を確認・手直ししてから動画化する
.venv/bin/python tools/make_video.py --genre money --theme "..." --script-only
.venv/bin/python tools/make_video.py --from-script content/scripts/money-001.json
```

### 2-2. 一次情報を埋める（`money` / `relationship` は必須）

このパイプラインの出力の価値は、**シーン4に入る「実際に会社を回している人しか
言えないこと」**にある。ここが空だと類型D（AI量産）と区別がつかず、
2026年のプラットフォーム規制の直撃を受ける（[01](./01_市場分析.md) 4章）。

**AIには本人の実体験を書かせない。** LLMは「何を入れるべきか」だけを書き、
`【要実体験】` という目印を残す。

```bash
$ .venv/bin/python tools/make_video.py --genre money --theme "..." --script-only
  ⚠️ 一次情報が未記入です（2箇所）: シーン4のcaption、シーン4のnarration
     content/scripts/money-001.json を開いて 「【要実体験】」を実際の内容に
     置き換え、--from-script で作り直してください。
```

生成された台本:

```json
{
  "first_hand": "自分の会社の直近の社会保険料の月額決定通知や給与明細を確認し、
                 役員報酬額に対して会社負担と個人負担がそれぞれいくらになっているかを整理する。",
  "scenes": [
    ...
    { "caption": "【要実体験】実額を公開",
      "narration": "【要実体験】自社の役員報酬額と、そこにかかる社保の会社負担・個人負担の実額" },
    ...
  ]
}
```

`first_hand` に「何を調べればよいか」が書いてある。それを見て自分の数字を確認し、
シーン4の `caption` / `narration` を実際の内容に書き換えてから `--from-script` で作り直す。

| ジャンル | スロット |
|---|---|
| `money` / `relationship` | **必須**。埋めずに投稿しない |
| `trivia` | 不要（`first_hand` は空。一次情報が原理的に乗らない） |

> ⚠️ 警告は出るが**処理は止めない**（絵を先に確認したいことがあるため）。
> 埋めないまま投稿すると、**画面に `【要実体験】` が焼き込まれたまま公開される。**

### 2-3. 投稿（YouTube Shorts）

```bash
# 初回のみ: ブラウザが開いて認可される
.venv/bin/python tools/publish_youtube.py --auth

# 未投稿を全部（既定は限定公開。中身を見てから公開へ切り替える）
.venv/bin/python tools/publish_youtube.py --all

# 1本だけ公開で
.venv/bin/python tools/publish_youtube.py content/out/money-001.mp4 --privacy public
```

同名の台本JSONがあれば、タイトル・説明・タグは自動で埋まる。
`content/out/.published_youtube.json` に投稿済みを記録するので `--all` は二重投稿しない。

| 出力 | 内容 | git |
|---|---|---|
| `content/scripts/<id>.json` | 台本。手で直して `--from-script` で作り直せる | 追跡する |
| `content/assets/<id>/` | 背景・音声・シーンmp4・クレジット（中間物） | 除外 |
| `content/assets/stock/` | Pexelsから取得した素材のキャッシュ | 除外 |
| `content/assets/bgm/` | BGM音源（本人が用意） | 除外 |
| `content/out/<id>.mp4` | 完成した縦動画 | 除外 |

## 3. 前提

| 項目 | 要否 | 備考 |
|---|---|---|
| ffmpeg / ffprobe | **必須** | `brew install ffmpeg` |
| 日本語フォント | **必須** | `/Library/Fonts/ヒラギノ角ゴ StdN W8.otf`（極太でないと小画面で潰れる） |
| `.venv` | **必須** | 構築済み。macOSはPEP 668でシステムPythonに入らないため venv 必須 |
| `ANTHROPIC_API_KEY` | 台本生成時 | `~/repo/.cowork-secrets/anthropic_key.txt`（**要取得**） |
| Pexels APIキー | 任意 | `~/repo/.cowork-secrets/pexels_key.txt`。あれば背景が**映像**になる（登録不可なら無くてよい） |
| Openverse | 背景（既定） | **キー不要**。CC0/PDの縦写真を検索し、Ken Burnsで動かす |
| VOICEVOXエンジン | 音声（推奨） | `~/.voicevox/*/run` か VOICEVOX.app。無ければ `say` にフォールバック |
| BGM音源 | 導入済み | `content/assets/bgm/`。Scott Buckley 3曲（CC BY 4.0）。**曲と同名の `.txt` にクレジットを対で置く** |
| YouTube OAuthクライアント | 投稿時 | `~/repo/.cowork-secrets/youtube_client_secret.json`（**要取得**） |

APIキーが無い場合は自動でテンプレ台本にフォールバックし、後段の検証だけ先に通せる。

### YouTube OAuthクライアントの取得手順

| # | やること | 場所 |
|---|---|---|
| 1 | プロジェクトを作る（名前は何でもよい） | [Cloud Console](https://console.cloud.google.com/projectcreate) |
| 2 | **YouTube Data API v3** を有効にする | [APIライブラリ](https://console.cloud.google.com/apis/library/youtube.googleapis.com) |
| 3 | OAuth同意画面を作る。ユーザーの種類は**外部** | [Google Auth Platform](https://console.cloud.google.com/auth/overview) |
| 4 | **公開ステータスを「本番環境」にする**（下の警告を参照） | 同上 → 対象（Audience） |
| 5 | OAuthクライアントIDを作る。種類は**デスクトップアプリ** | [認証情報](https://console.cloud.google.com/auth/clients) |
| 6 | JSONをダウンロードして `~/repo/.cowork-secrets/youtube_client_secret.json` に置く | ローカル |
| 7 | `.venv/bin/python tools/publish_youtube.py --auth` | ターミナル |

> ⚠️ **公開ステータスを「テスト中」のままにしないこと。**
> テスト中の外部アプリは**リフレッシュトークンが7日で失効**する。
> 自動投稿がエラーも出さずに止まり、`invalid_grant: Token has been expired or revoked`
> が出て初めて気づくことになる。「本番環境」に切り替えれば無期限になる。

手順7でブラウザに「このアプリはGoogleで確認されていません」と出るが、
**自分専用のアプリなので問題ない**（`詳細` → `（安全でないページ）に移動` で進む）。
Google審査は他人に配布する場合にだけ必要。

### チャンネル設定でAPIからできること・できないこと

```bash
.venv/bin/python tools/publish_youtube.py --channel                          # 現状の確認
.venv/bin/python tools/publish_youtube.py --description-file data/channel_description.md
```

| 項目 | API | 備考 |
|---|---|---|
| 説明文 | ⭕️ | `--description` / `--description-file` |
| 動画の投稿 | ⭕️ | |
| **チャンネル名** | **✗** | **APIは200を返すが実際には反映されない**（既知の挙動）。手で変更する |
| ハンドル（@xxx） | ✗ | APIに変更手段が無い。手で変更する |

チャンネル名とハンドルは YouTube Studio → カスタマイズ → 基本情報 から変更する。
`--rename` は変更後に読み直して検証し、反映されていなければその旨を出す
（成功したと偽らないため）。**チャンネル名の変更は14日で2回まで**。

### シークレットの置き場

`~/repo/.cowork-secrets/` に置く（**コミットしないこと**）。
`~/dev/` → `~/repo/` の移動実績があるため、コードは複数候補を順に探すようにしてある
（1箇所決め打ちだと、トークンを置いても見つからず静かに壊れる）。

## 4. 設計判断（なぜこうしたか）

### 4-1. 背景はストック映像（Pexels）。グラデーションをやめた

> 改訂（2026-07-29）: 当初は「字幕が主役だから背景はグラデーションで足りる」としていたが、
> **これは判断ミスだった**。フィードの最低水準を下回る画は1秒でスワイプされるため、
> 出てくる数字が「ジャンルの優劣」ではなく「作りの安っぽさ」を測ってしまい、
> **2週間テストそのものが成立しない**。[03_トレンド調査.md](./03_トレンド調査.md) 1章の
> 「2〜3秒に1回の視覚変化」も、グラデーション1枚では満たせなかった。

現在は台本の `image_prompt` から検索語を作り、シーンごとにストック素材を敷いている。
調達は **Pexels映像（APIキーがあれば）→ Openverse写真（キーレス・CC0/PDのみ）** の順。
Pexelsにサインアップできない環境でも、Openverseだけで実写背景が成立する
（写真は render 側の Ken Burns で動かす）。取得済みの素材は
`content/assets/stock/` にキャッシュし、同じ検索語では再ダウンロードしない。

Openverseの検索結果は並び順が信用できず、商品パッケージ等の「写真だが素材ではない」
画像が先頭に来ることがある。そこで**候補のサムネイルをClaude（vision）に見せて選別**する
（1シーン3判定まで・数円程度。判定失敗時は先頭候補で続行するのでパイプラインは止まらない）。

画像・動画**生成AI**を使っていない理由は変わらない: テスト期に1本数十円を払う理由が無く、
かつ生成映像は「AI量産（類型D）」の見た目に寄る。**当たったフォーマットが決まってから**
検討する（[#35](https://github.com/bashaka-sawabe/personal-sns-operation/issues/35)）。
差し替え口は `tools/pipeline/media.py` の `background()` 一箇所に閉じてある。

### 4-2. 音声はVOICEVOX。`say` をやめた（本人の声はまだ）

> 改訂（2026-07-29）: macOS `say`（Kyoko）は機械読みが露骨で、背景と並ぶ
> 「安っぽさ」の主因だった。**VOICEVOX**（無料・ローカル・商用可）に差し替えた。
> エンジンは `~/.voicevox/*/run` または VOICEVOX.app を自動起動し、
> 無い環境では `say` にフォールバックする。

VOICEVOXは**キャラクター名のクレジット表記が利用条件**。投稿時の説明文に
`VOICEVOX:<キャラ名>` を自動で入れる（`tools/publish_youtube.py`）。
TikTokは**AI生成コンテンツのラベル表示が必須**なので、合成音声を使う間は必ず付ける。

ジャンル確定後、本人の声に差し替える方針は変わらない
（[07_ロードマップ.md](./07_ロードマップ.md) の Phase 2）。
声を本人にすることは「人間が作っている証明」でもあり、**量産AI判定の回避策そのもの**
（[01_市場分析.md](./01_市場分析.md) 4章）。**顔より先に声を出す。**

### 4-3. 字幕はフレーズ単位で音声に同期させる

ナレーションを句読点でフレーズに割り、**フレーズごとに合成→その尺だけ字幕を出す**。
タイミング計算が不要になり（フレーズ音声の長さ＝表示時間）、
[03_トレンド調査.md](./03_トレンド調査.md) 1章の「2〜3秒に1回の視覚変化」が構造的に満たされる。
数字・単位はキーワードとして自動で色を変える。シーン見出しは画面上部に置き続ける
（スクリーンショットされたときに1枚で意味が通る）。

### 4-4. BGMは素材があるときだけ、ダッキング付きで敷く

`content/assets/bgm/` の音源をループで敷き、**ナレーションが鳴っている間は
サイドチェーンで自動的に音量を下げる**。無ければ無音のまま通す。

> 改訂（2026-07-29）: 連結時に**映像を再エンコードしない**（`-c:v copy`）。
> BGMのフィルタグラフと `libx264` を同時に走らせると、音声だけが末尾2秒ほど
> 早くEOFする（切れる位置が実行ごとにブレるので、フィルタの記述ではなくffmpeg側の競合）。
> 最後のシーンのCTAが無音になり、**絵だけ流れて音が消える＝再生が止まったように見える**。
> シーンmp4は同一パラメータのh264なので copy で繋がる。
> バグが消えるだけでなく世代劣化も無くなり、連結が約10倍速くなる。
> 完成品は必ず**音声尺と映像尺が一致すること**を確認する。

導入済みの3曲は Scott Buckley（CC BY 4.0）。選定理由は、作者が
**Content ID に登録しないことを明言している**ため（新規チャンネルに
著作権の申し立てが付くリスクを避ける）。CC BY はクレジット表記が利用条件なので、
**曲と同名の `.txt`（サイドカー）にクレジット文を対で置く**。
サイドカーの中身は投稿時の説明文へ自動で入る。曲を足すときも必ず対で置くこと。

### 4-5. 静止画は「寄り／引き＋パン」で動かす（中央ズームは止まって見える）

> 改訂（2026-07-29）: 当初は毎秒1.8%の中央ズームだけだった。
> 1フレームあたり0.06%では目が変化を拾えず、さらに**中心が動かないと画面の端に
> 手がかりが出ない**ため、静止画そのものに見えた。

シーン番号で動きを切り替える（寄りながら右へ／引きながら下へ／寄りながら左へ／
引きながら上へ）。ズームは 1.05〜1.24 の範囲で、**下限を1.0にしない**のは、
等倍だと切り出し矩形の可動域が消えてパンが止まるため。
連続するシーンで動きが揃わないので、切り替わりも認識されやすくなる。

### 4-6. シーンごとに独立したmp4を書き出してから連結している

1本のフィルタグラフで全部やると、1シーン失敗しただけで全体が落ち、
どのシーンが原因か分からない。分割しておくと切り分けが効く。

### 4-7. 尺は音声に合わせる

映像を音に合わせることで、台本の長短をそのまま許容できる。
尺の手調整が発生しない＝人の手が入らない＝自動化が壊れない。

### 4-8. バッチは1本落ちても止めない

`--batch` は失敗した本をスキップして残りを作り切り、最後にまとめて報告する。
夜間に流して朝に結果を見る運用を前提にしている。

## 6-2. プラットフォームの役割分担

| PF | 投稿 | 役割 |
|---|---|---|
| **YouTube Shorts** | **自動（実装済）** | **ストック**。検索経由で寿命が長く、1本が数ヶ月効き続ける。収益化条件も最も明確 |
| Threads | 自動（未実装・最軽量） | テスト場。テキストで反応を見てから動画化する |
| Instagram Reels | 自動（未実装） | 主戦場。平均年齢37歳で仕事・お金の文脈が刺さる |
| TikTok | サードパーティ経由 | 発見エンジン。0フォロワーでも当たる |

YouTubeだけ性質が違う。IG/TikTokは**フロー**（数日で消える）、YouTubeは**ストック**。
同じ12本でも、YouTubeに置いた分だけが3ヶ月後も効いている状態になるので、
テスト期でも必ず4面すべてに出す。

## 7. 禁止事項（[08](./08_自動化.md) 2章を継承）

自動フォロー・自動いいね・自動DM・フォロワー購入は3PFすべてで規約違反。
**投稿直後30〜60分のコメント返信は手動**。ここは自動化しないほうがアルゴリズム上も有利。
