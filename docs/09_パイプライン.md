# 09. 動画生成パイプライン

> 最終更新: 2026-08-02（v6.1: 演出をチャンネル別に持たせる） ／ 前提: [08_自動化.md](./08_自動化.md)（自動化の線引き・素材規約）、[06_KPI・運用.md](./06_KPI・運用.md)（判定指標）

## 1. これは何か

**ずんだもん×四国めたんの掛け合い**縦動画を自動で作るパイプライン。
チャンネルごとの型・配役は `data/channels/<ch>.json` が持ち、コードは共通（[05](./05_コンテンツ企画.md) 1章）。

> **v5（2026-08-02）**: `girls` / `meme` の入力は「テーマ1行」から**採用スレ**
> （`data/threads/`・目視選別済み）に変わる（[04](./04_戦略.md) 2-2章）。
> スレ収集・目視選別は [#88](https://github.com/bashaka-sawabe/personal-sns-operation/issues/88)、
> 台本生成の刷新（オチ逆算の翻案）は [#89](https://github.com/bashaka-sawabe/personal-sns-operation/issues/89) で実装する。
> 実装が終わるまでは下記の旧フロー（テーマ1行）のまま動く。`biz` は従来通りテーマ＋一次情報。

```
girls / meme: 採用スレ（data/threads/）      biz: チャンネル × テーマ（1行）
        ↓ Claude API（claude-opus-5 / JSON強制・スレのオチから逆算して掛け合いに翻案）
掛け合い台本JSON（フック＋本編3点＋締めの5シーン。各シーン1〜3行のセリフ）
        ↓ Pexels API（image_prompt→検索語）／VOICEVOX（話者別・フレーズ単位で合成）
ストック映像＋セリフ音声＋話者アイコン
        ↓ ffmpeg（話者色の同期字幕・話者アイコンの切り替え・BGMダッキング・連結）
content/out/<id>.mp4  （1080×1920 / 30fps / H.264+AAC）
```

外部素材が無くても止まらない。背景は **Pexels映像（キーがあれば）→ Openverse写真
（キーレス）→ グラデーション** の順で、音声は **VOICEVOX → macOS `say`** の順で
自動フォールバックする（グラデ・`say` まで落ちた品質で**投稿はしない**）。

## 2. 使い方

### 2-1. 生成

```bash
# 1本作る
.venv/bin/python tools/make_video.py --channel biz --theme "法人化で税金は減るのか"

# APIキー無しで疎通確認（テンプレ台本＋ローカル素材で最後まで通る）
.venv/bin/python tools/make_video.py --channel biz --theme "テスト" --offline

# 2週間テストの本体。3チャンネル12本をまとめて生成する
.venv/bin/python tools/make_video.py --batch data/themes.md

# 台本だけ先に作り、中身を確認・手直ししてから動画化する
.venv/bin/python tools/make_video.py --channel biz --theme "..." --script-only
.venv/bin/python tools/make_video.py --from-script content/scripts/biz/biz-001.json
```

旧形式（ナレーション形式）の台本を `--from-script` に渡すと `PipelineError` で明確に落ちる
（v3の台本はv4では使えない。作り直す）。

### 2-2. 一次情報を埋める（`biz` は必須）

このパイプラインの出力の価値は、**シーン4に入る「実際に会社を回している人しか
言えないこと」**にある。ここが空だと類型D（AI量産）と区別がつかず、
2026年のプラットフォーム規制の直撃を受ける（[01](./01_市場分析.md) 4章）。

**AIには本人の実体験を書かせない。** LLMは「何を入れるべきか」だけを書き、
`【要実体験】` という目印を残す。

> 一次情報として出すのは**体験・手順・判断・失敗談**。
> **会社の具体的な金額（実額）は公開しない**方針（[04](./04_戦略.md) 8章）のため、
> スロットが金額を求める台本にはしない（生成プロンプト側でも禁止している）。

```bash
$ .venv/bin/python tools/make_video.py --channel biz --theme "..." --script-only
  ⚠️ 一次情報が未記入です（2箇所）: シーン4のcaption、シーン4のセリフ2
     content/scripts/biz/biz-001.json を開いて 「【要実体験】」を実際の内容に
     置き換え、--from-script で作り直してください。
```

生成された台本（掛け合い形式）:

```json
{
  "first_hand": "独立1年目に実際に見落とした支払いを思い出し、
                 いつ届いて、どう乗り切ったかを1件分書き出す。",
  "scenes": [
    ...
    { "caption": "【要実体験】中の人の誤算",
      "dialogue": [
        { "speaker": "zundamon", "text": "実際はどうだったのだ？" },
        { "speaker": "metan", "text": "【要実体験】独立1年目に見落とした支払いと、その顛末" }
      ] },
    ...
  ]
}
```

`first_hand` に「何を思い出して書けばよいか」が書いてある。それを見て自分の体験を書き起こし、
シーン4の `caption` / セリフを実際の内容に書き換えてから `--from-script` で作り直す。

| チャンネル | スロット |
|---|---|
| `biz` | **必須**。埋めずに投稿しない。あわせて「中の人」言及が1本1回入る（[04](./04_戦略.md) 7章） |
| `girls` / `meme` | 不要（`first_hand` は空） |

> ⚠️ **生成は止めない**（絵を先に確認したいことがあるため）。警告だけ出して動画はできる。
> 代わりに**投稿側で止める**。`publish_youtube.py` は台本に `【要実体験】` が残る動画を
> 投稿せず、理由を出して落ちる（`--all` はその1本だけスキップして残りを投稿し、
> 末尾にスキップ一覧を出す）。事前確認は `--dry-run`。
>
> ```bash
> $ .venv/bin/python tools/publish_youtube.py --all --dry-run
> 投稿予定: girls-001.mp4 → 「飲み会を感じよく断る一言 #Shorts」 (unlisted)
>
> 投稿しなかった動画（1本）:
>   - biz-001.mp4: 一次情報が未記入です（2箇所: シーン4のcaption、シーン4のセリフ3）。...
> ```
>
> 台本JSONが見つからない動画（旧世代の mp4 など）は検査しようがないので対象外。

### 2-3. 投稿（YouTube Shorts）

```bash
# 初回のみ: ブラウザが開いて認可される
.venv/bin/python tools/publish_youtube.py --auth

# 何が上がって何が止まるかを先に見る（APIを呼ばない）
.venv/bin/python tools/publish_youtube.py --all --dry-run

# 未投稿を全部（既定は限定公開。中身を見てから公開へ切り替える）
.venv/bin/python tools/publish_youtube.py --all

# 1本だけ公開で
.venv/bin/python tools/publish_youtube.py content/out/biz-001.mp4 --privacy public

# レビューを通ったものを公開に切り替える（限定公開 → 公開）
.venv/bin/python tools/publish_youtube.py --release girls-001 meme-002
```

`--release` は台帳が `posted`（限定公開で上がっていて、まだレビュー前）の行しか受け付けない。
レビュー前や公開済みを指定すると止まる。**公開は取り消せない**ので、
先に `--release ... --dry-run` で対象を確認する。切り替えると台帳が `measuring` になる。

同名の台本JSON（`content/scripts/*/` を横断して探す）があれば、タイトル・説明・タグは
自動で埋まる。説明文には `credits.txt`（VOICEVOX・BGM・効果音のクレジット）が自動で入る。
`content/out/.published_youtube.json` に投稿済みを記録するので `--all` は二重投稿しない。
一次情報が未記入の動画は投稿前に弾く（4章の `【要実体験】`）。

> チャンネル別の投稿先振り分けは
> [#29](https://github.com/bashaka-sawabe/personal-sns-operation/issues/29) で実装する。
> YouTubeは3チャンネルに分ける方針（[00](./00_サマリー.md) 3章）なので、
> **チャンネルごとに別のOAuthトークンが要る**。1つのGoogleアカウントに
> ブランドアカウントがぶら下がる形なので、同意画面で「どのチャンネルとして許可するか」を
> 選んだ結果がトークンに焼き付く。置き場の規約:
>
> | ch | トークン |
> |---|---|
> | `biz` | `~/repo/.cowork-secrets/youtube_token_biz.json` |
> | `girls` | `~/repo/.cowork-secrets/youtube_token_girls.json` |
> | `meme` | `~/repo/.cowork-secrets/youtube_token_meme.json` |
>
> 投稿先は台本JSONの `channel` から自動で引くので、投稿時にチャンネルの指定は要らない。
> トークンを取るときだけ `--as` でどのチャンネルかを伝える:
>
> ```bash
> .venv/bin/python tools/publish_youtube.py --auth --as girls   # 同意画面でgirlsを選ぶ
> ```
>
> `--auth` は完了時に「このトークンのチャンネル: 〜」を出す。**同意画面で選び間違えると
> 投稿先がずれる**ので、ここで必ず確認する。投稿時もチャンネルごとに1回、実際の投稿先名を出す。
>
> 既存の `youtube_token.json` は biz のものとして読む（改名しなくても動く）。
> **クォータ（1日10,000ユニット＝6本）は Google Cloudプロジェクト単位**なので、
> チャンネルを分けても上限は増えない。12本はやはり2日に分かれる。

### 2-4. 投稿（Threads / Instagram Reels）

```bash
# Threads: テキストで反応を見てから動画化する（テスト場）
.venv/bin/python tools/publish_threads.py content/scripts/meme/meme-016.json
.venv/bin/python tools/publish_threads.py --all --dry-run

# Instagram Reels: 動画を投稿する（主戦場）
.venv/bin/python tools/publish_instagram.py content/scripts/meme/meme-016.json
```

トークンは `threads_access_token.txt` / `instagram_access_token.txt` をシークレット置き場に置く。
無ければ各コマンドが取得手順を日本語で出して落ちる。台帳（`.published_threads.json` /
`.published_instagram.json`）で二重投稿は防ぐ。

**IGの動画URL問題の解決（決定）**: Content Publishing API は動画を公開URLでしか
受け取らない。恒久ホスティングは契約せず、**cloudflared の quick tunnel
（無料・アカウント不要）＋一時ローカルHTTPサーバ**で `content/out/` を投稿の間だけ
外に見せる方式にした（`publish_instagram.py` が自動で立てて落とす）。

- 理由: URLが必要なのはIGが動画を取りに来る数十秒だけ。そのためにS3等の常設バケットを
  持つと、認証情報の管理と公開範囲の管理が増える割に得るものがない
- 準備は `brew install cloudflared` のみ（未導入ならその旨を案内して落ちる）
- quick tunnel はURLが毎回変わる使い捨て。恒久配信には使わないこと
- 12本/日級の量産で不安定になったら、そのとき初めてR2等の常設に切り替える（[#168](https://github.com/bashaka-sawabe/personal-sns-operation/issues/168)）

### 2-5. 毎日3投稿の回し方（#168）

```bash
# 在庫と投稿計画の確認
.venv/bin/python tools/daily_run.py --dry-run

# 生成→限定公開投稿まで（1日1回）
.venv/bin/python tools/daily_run.py
```

`daily_run.py` は各チャンネル3本を目標に、**採用済み（人・委任）の在庫を先に消費し、
足りない分は候補から自動採用**して生成→限定公開投稿まで回す
（2026-08-08 本人決定・[#191](https://github.com/bashaka-sawabe/personal-sns-operation/issues/191)。条件と残る関所は [08](./08_自動化.md) 1章）。
fact系は裏取り付き候補のみ・meme は `check_criteria` の機械検問を通ったものだけが
自動採用される。自動採用分は計画出力に `←自動採用`、台帳に `adopted_by: auto` が付く。

毎朝10時の自動実行は launchd に登録済み（2026-08-08）:
`~/Library/LaunchAgents/com.bashaka.sns.daily-video.plist` が
`daily_run.py` を実行し、ログは `logs/daily_run.log` に追記される。

**クォータの壁**: アップロードは1本1,600ユニット・1プロジェクト1日10,000ユニット＝**6本**。
12本/日にする解決策は2つ（どちらも本人作業）:

| 案 | 手順 | 備考 |
|---|---|---|
| **プロジェクト分割（推奨）** | Google Cloudで2つ目のプロジェクトを作り、OAuthクライアントJSONを `youtube_client_secret_<ch>.json`（例: heisei / showa の2ch分）として置き、`--auth --as <ch>` で再認可 | `daily_run.py` はチャンネル専用secretの有無で自動的にクォータ枠を分けて数える |
| クォータ引き上げ申請 | [YouTube API Services - Audit and Quota Extension Form](https://support.google.com/youtube/contact/yt_api_form) | 審査に数週間かかることがある |

分割もクォータも無い間は、`daily_run.py` が**6本で止めて残りを翌日に回す**（黙って超えない）。
heisei の「◯◯選」はfactを6個消費するため日次には入れない（手動の特別編のみ）。

| 出力 | 内容 | git |
|---|---|---|
| `data/channels/<ch>.json` | チャンネル設定（ペルソナ・型・配役） | 追跡する |
| `content/scripts/<ch>/<id>.json` | 台本。手で直して `--from-script` で作り直せる | 追跡する |
| `content/assets/<id>/` | 背景・音声・シーンmp4・クレジット（中間物） | 除外 |
| `content/assets/icons/` | 話者アイコン。**90年代セル画風のAI生成人物顔で全話者統一**（#189・Canva生成、クレジットは各<key>.txt）。役柄・性別は声と一致させる。再生成時は`content/assets/<id>/icon_*.png`のキャッシュも消すこと。`tools/fetch_icons.py` で欠けが検品できる | 除外 |
| `content/assets/stock/` | Pexelsから取得した素材のキャッシュ | 除外 |
| `content/assets/bgm/` | BGM音源（本人が用意） | 除外 |
| `content/assets/se/` | 効果音（`tools/fetch_se.py` で取得） | 除外 |
| `content/out/<id>.mp4` | 完成した縦動画 | 除外 |

## 3. 前提

| 項目 | 要否 | 備考 |
|---|---|---|
| ffmpeg / ffprobe | **必須** | `brew install ffmpeg` |
| 日本語フォント | **必須** | `/Library/Fonts/ヒラギノ角ゴ StdN W8.otf`（極太でないと小画面で潰れる） |
| `.venv` | **必須** | 構築済み。macOSはPEP 668でシステムPythonに入らないため venv 必須 |
| `ANTHROPIC_API_KEY` | 台本生成時 | `~/repo/.cowork-secrets/anthropic_key.txt`（**要取得**） |
| Pexels APIキー | 任意 | `~/repo/.cowork-secrets/pexels_key.txt`。あれば背景が**映像**になる（登録不可なら無くてよい） |
| Openverse | 背景（既定） | **キー不要**。CC0/PDの縦写真を検索し、Ken Burnsで動かす |
| VOICEVOXエンジン | 音声（推奨） | `~/.voicevox/*/run` か VOICEVOX.app。無ければ `say` にフォールバック |
| BGM音源 | 導入済み | `content/assets/bgm/`。Scott Buckley 3曲（CC BY 4.0）。**曲と同名の `.txt` にクレジットを対で置く** |
| 効果音 | 演出（推奨） | `.venv/bin/python tools/fetch_se.py` で効果音ラボから取得。**商用無料・クレジット不要・収益化OK**。ただし**Content ID登録は規約で禁止**。無ければ効果音なしで続行 |
| YouTube OAuthクライアント | 投稿時 | `~/repo/.cowork-secrets/youtube_client_secret.json`（**要取得**） |

APIキーが無い場合は自動でテンプレ台本にフォールバックし、後段の検証だけ先に通せる。

### YouTube OAuthクライアントの取得手順

| # | やること | 場所 |
|---|---|---|
| 1 | プロジェクトを作る（名前は何でもよい） | [Cloud Console](https://console.cloud.google.com/projectcreate) |
| 2 | **YouTube Data API v3** を有効にする | [APIライブラリ](https://console.cloud.google.com/apis/library/youtube.googleapis.com) |
| 3 | OAuth同意画面を作る。ユーザーの種類は**外部** | [Google Auth Platform](https://console.cloud.google.com/auth/overview) |
| 4 | **公開ステータスを「本番環境」にする**（下の警告を参照） | 同上 → 対象（Audience） |
| 5 | OAuthクライアントIDを作る。種類は**デスクトップアプリ** | [認証情報](https://console.cloud.google.com/auth/clients) |
| 6 | JSONをダウンロードして `~/repo/.cowork-secrets/youtube_client_secret.json` に置く | ローカル |
| 7 | `.venv/bin/python tools/publish_youtube.py --auth` | ターミナル |

> ⚠️ **公開ステータスを「テスト中」のままにしないこと。**
> テスト中の外部アプリは**リフレッシュトークンが7日で失効**する。
> 自動投稿がエラーも出さずに止まり、`invalid_grant: Token has been expired or revoked`
> が出て初めて気づくことになる。「本番環境」に切り替えれば無期限になる。

手順7でブラウザに「このアプリはGoogleで確認されていません」と出るが、
**自分専用のアプリなので問題ない**（`詳細` → `（安全でないページ）に移動` で進む）。
Google審査は他人に配布する場合にだけ必要。

### チャンネル設定でAPIからできること・できないこと

```bash
.venv/bin/python tools/publish_youtube.py --channel                          # 現状の確認
.venv/bin/python tools/publish_youtube.py --description-file data/profile_youtube_biz.md
```

| 項目 | API | 備考 |
|---|---|---|
| 説明文 | ⭕️ | `--description` / `--description-file` |
| 動画の投稿 | ⭕️ | |
| **チャンネル名** | **✗** | **APIは200を返すが実際には反映されない**（既知の挙動）。手で変更する |
| ハンドル（@xxx） | ✗ | APIに変更手段が無い。手で変更する |

チャンネル名とハンドルは YouTube Studio → カスタマイズ → 基本情報 から変更する。
`--rename` は変更後に読み直して検証し、反映されていなければその旨を出す
（成功したと偽らないため）。**チャンネル名の変更は14日で2回まで**。

### シークレットの置き場

`~/repo/.cowork-secrets/` に置く（**コミットしないこと**）。
`~/dev/` → `~/repo/` の移動実績があるため、コードは複数候補を順に探すようにしてある
（1箇所決め打ちだと、トークンを置いても見つからず静かに壊れる）。

## 4. 設計判断（なぜこうしたか）

### 4-1. 背景はストック映像（Pexels）。グラデーションをやめた

> 改訂（2026-07-29）: 当初は「字幕が主役だから背景はグラデーションで足りる」としていたが、
> **これは判断ミスだった**。フィードの最低水準を下回る画は1秒でスワイプされるため、
> 出てくる数字が「ジャンルの優劣」ではなく「作りの安っぽさ」を測ってしまい、
> **2週間テストそのものが成立しない**。[03_トレンド調査.md](./03_トレンド調査.md) 1章の
> 「2〜3秒に1回の視覚変化」も、グラデーション1枚では満たせなかった。

#### 背景は挿絵ではなく「目を離させないノイズ」（2026-08-05・[#141](https://github.com/bashaka-sawabe/personal-sns-operation/issues/141)）

**台本の `image_prompt` から検索語を作る方式をやめた。** シーンの内容から背景を引くと、
画面が台本を復唱するだけの挿絵になる。実際 `meme-012` は
「妻がスカートを履かない」というスレに対して背景がクローゼット・たたんだ服・
服を持つ男性で、**画面に見る理由が無かった**。

ロンロン（51.2万）は**2chと無関係の飯テロ／ASMR映像**を全画面で流し、0.4秒ごとに
カットしている（[02](./02_競合分析.md) 2章）。背景は説明ではなく、目を離させないための刺激。

そこで検索語は `data/channels/<ch>.json` の `style.bg_queries`（英語の系統リスト）から引く。

| ch | 背景の系統 | 理由 |
|---|---|---|
| `meme` | 飯テロ・ASMR（溶けるチーズ／流れるチョコ／砂を切る） | スレの内容と無関係でよい。刺激だけが仕事 |
| `showa` | 工場・溶接の火花・旧車のエンジン | 時代の空気は要る。ただし個別の逸話は再現しない |
| `heisei` | **`bg_queries` を置かない**（`image_prompt` のまま） | 商品そのものが懐古の対象で、画が内容と一致していることに意味がある（[02](./02_競合分析.md) 4章） |

**1本の検索語で取れなくてもグラデには落とさず、リストの次の語で引き直す。**
`showa-001` は「昭和の工場」で何も取れず、**背景が真っ黒のグラデのまま完成**していた。

調達は **Pexels映像（APIキーがあれば）→ Openverse写真（キーレス・CC0/PDのみ）** の順。
Pexelsにサインアップできない環境でも、Openverseだけで実写背景が成立する
（写真は render 側の Ken Burns で動かす）。取得済みの素材は
`content/assets/stock/` にキャッシュし、同じ検索語では再ダウンロードしない。

Openverseの検索結果は並び順が信用できず、商品パッケージ等の「写真だが素材ではない」
画像が先頭に来ることがある。そこで**候補のサムネイルをClaude（vision）に見せて選別**する
（1シーン3判定まで・数円程度。判定失敗時は先頭候補で続行するのでパイプラインは止まらない）。

画像・動画**生成AI**を使っていない理由は変わらない: テスト期に1本数十円を払う理由が無く、
かつ生成映像は「AI量産（類型D）」の見た目に寄る。**当たったフォーマットが決まってから**
検討する（[#35](https://github.com/bashaka-sawabe/personal-sns-operation/issues/35)）。
差し替え口は `tools/pipeline/media.py` の `background()` 一箇所に閉じてある。

### 4-2. 音声はVOICEVOXの2話者（キャラと声は不可分）

> 改訂（2026-07-30・v4）: 掛け合い形式に伴い、セリフごとに話者を持ち、
> ずんだもん（スタイルID 3）・四国めたん（同 2）の声で合成する。
> 話者IDは `tools/pipeline/channels.py` の `CHARACTERS` に固定してある。
> **キャラの声は差し替えない**（声＝キャラの同一性。docs/04 7章）。
> エンジンは `~/.voicevox/*/run` または VOICEVOX.app を自動起動し、
> 無い環境では `say` にフォールバックする（疎通確認用。投稿品質ではない）。

VOICEVOXは**キャラクター名のクレジット表記が利用条件**（[08](./08_自動化.md)）。
使った話者ぶんの `VOICEVOX:<キャラ名>` を `credits.txt` に書き出し、
投稿時の説明文に自動で入る（`tools/publish_youtube.py`）。
TikTokは**AI生成コンテンツのラベル表示が必須**なので、合成音声を使う間は必ず付ける。

本人の声は「差し替え」ではなく **Phase 2の共演**で入る
（[#36](https://github.com/bashaka-sawabe/personal-sns-operation/issues/36)・[04](./04_戦略.md) 7章）。
人の声が乗ることは「人間が作っている証明」でもある（[01](./01_市場分析.md) 4章）。

### 4-3. 字幕はフレーズ単位で音声に同期させる

セリフを句読点でフレーズに割り、**フレーズごとに合成→その尺だけ字幕を出す**。
タイミング計算が不要になり（フレーズ音声の長さ＝表示時間）、
[03_トレンド調査.md](./03_トレンド調査.md) 1章の「2〜3秒に1回の視覚変化」が構造的に満たされる。
**字幕は話者の色で塗る**（ずんだもん=黄緑・めたん=ピンク。話者アイコンと対で
「誰の声か」を伝える）。数字・単位はキーワードとして自動で強調色に変える。

#### オチのパワーワードだけ特大にする（2026-08-05・[#142](https://github.com/bashaka-sawabe/personal-sns-operation/issues/142)）

全セリフが同じ大きさだと、**どこが山なのか画面から分からない**。
`showa-001` は熱血経営者の怒声「自分で走らせたか！」が他の行と同じ極小サイズで流れていた。

ロンロンは**復唱させたい1語だけを特大の青/黄で画面いっぱいに出す**（[02](./02_競合分析.md) 2章）。
コメント欄がその語の復唱で埋まり、エンゲージメントになる。

- 台本に `powerword`（必須）を持たせ、その語を含むフレーズは
  **前後の言葉を捨てて、その語だけを画面中央に特大で出す**
- 色は金（`00D7FF`）。キャラ色とは別系統にして「特別な1語」であることを示す
- その瞬間は**話者アイコンも消す**。1語だけを見せる
- 引用スレから作るときは、**採用時に決めた語がそのまま渡る**
  （[05](./05_コンテンツ企画.md) 3章。台本側で選び直させると、
  「スレに実在する語か」の検査が効かなくなる）
- 語がどのセリフにも入っていないと特大字幕が出ないので、`dialogue_issues()` が警告する

> v5: シーンごとのセクション見出しは**廃止方向**（[#93](https://github.com/bashaka-sawabe/personal-sns-operation/issues/93)）。
> 登録者10万人超の同形式チャンネルはセクション見出しを出さず、**スレタイ（フック）を
> 全編上部に常時表示**している（[04](./04_戦略.md) 2-2章の判断基準）。
> 「スクショ1枚で意味が通る」要件はスレタイ常時表示で維持する。

### 4-4. BGMは素材があるときだけ、ダッキング付きで敷く

`content/assets/bgm/` の音源をループで敷き、**ナレーションが鳴っている間は
サイドチェーンで自動的に音量を下げる**。無ければ無音のまま通す。

> 改訂（2026-07-29）: 連結時に**映像を再エンコードしない**（`-c:v copy`）。
> BGMのフィルタグラフと `libx264` を同時に走らせると、音声だけが末尾2秒ほど
> 早くEOFする（切れる位置が実行ごとにブレるので、フィルタの記述ではなくffmpeg側の競合）。
> 最後のシーンのCTAが無音になり、**絵だけ流れて音が消える＝再生が止まったように見える**。
> シーンmp4は同一パラメータのh264なので copy で繋がる。
> バグが消えるだけでなく世代劣化も無くなり、連結が約10倍速くなる。
> 完成品は必ず**音声尺と映像尺が一致すること**を確認する。

導入済みの3曲は Scott Buckley（CC BY 4.0）。選定理由は、作者が
**Content ID に登録しないことを明言している**ため（新規チャンネルに
著作権の申し立てが付くリスクを避ける）。CC BY はクレジット表記が利用条件なので、
**曲と同名の `.txt`（サイドカー）にクレジット文を対で置く**。
サイドカーの中身は投稿時の説明文へ自動で入る。曲を足すときも必ず対で置くこと。

### 4-5. 静止画は「寄り／引き＋パン」で動かす（中央ズームは止まって見える）

> 改訂（2026-07-29）: 当初は毎秒1.8%の中央ズームだけだった。
> 1フレームあたり0.06%では目が変化を拾えず、さらに**中心が動かないと画面の端に
> 手がかりが出ない**ため、静止画そのものに見えた。

シーン番号で動きを切り替える（寄りながら右へ／引きながら下へ／寄りながら左へ／
引きながら上へ）。ズームは 1.05〜1.24 の範囲で、**下限を1.0にしない**のは、
等倍だと切り出し矩形の可動域が消えてパンが止まるため。
連続するシーンで動きが揃わないので、切り替わりも認識されやすくなる。

### 4-6. シーンごとに独立したmp4を書き出してから連結している

1本のフィルタグラフで全部やると、1シーン失敗しただけで全体が落ち、
どのシーンが原因か分からない。分割しておくと切り分けが効く。

### 4-7. 尺は音声に合わせる

映像を音に合わせることで、台本の長短をそのまま許容できる。
尺の手調整が発生しない＝人の手が入らない＝自動化が壊れない。

### 4-8. 立ち絵をやめ、話者アイコンにした（2026-08-05・[#140](https://github.com/bashaka-sawabe/personal-sns-operation/issues/140)）

**旧方式（立ち絵を左右の下端に2体固定）は捨てた。** 理由は2つ、どちらも実害が出た。

1. **3人目以降を出す場所が無い。** `meme-012` は5人が喋ったのに画面は
   ずんだもん・めたんの2体固定で、玄野が喋っても虎太郎が喋っても画面が変わらなかった
2. **素材が無いキャラは画面に出られない。** `showa-001` では叫んでいる龍星の立ち絵が無く、
   **主役が画面に存在しない**動画ができた

ロンロンの天秤（51.2万）は立ち絵を置かず、**中央の丸アイコンを話者ごとに切り替える**
ことで1本に何人でも登場させている（[02](./02_競合分析.md) 2章）。同じ方式にした。

- アイコンは**キャラ色と名前からその場で生成する**。素材の調達がブロッカーにならない
- 表示するのは**今喋っている1人だけ**。話者が変わると画面が切り替わる
- 出す顔ぶれは配役ではなく**そのシーンで実際に喋る人**から作る。
  `cast` に載っていない脇役が喋っても、ちゃんとアイコンが出る
- 差し替えたいときだけ `content/assets/icons/<キャラ>.png` を置く。
  規約のある素材を使うなら、BGMと同じく**同名の `.txt` にクレジットを対で置く**

これに伴い `cast` の人数制限（2人ちょうど）も撤廃した。人数の上限はコードで決めない。

**アイコンの中身はVOICEVOXキャラの顔ではなく、90年代セル画風のAI生成人物顔で全話者統一する**
（2026-08-07・[#189](https://github.com/bashaka-sawabe/personal-sns-operation/issues/189) 本人決定。
いらすとや→#154、雑多なAI生成→#179 を経て、絵柄バラバラの反省から一括統一に落ち着いた）。
参照チャンネルの実測で、どこもVOICEVOXキャラの絵を出していないことが分かった
（ロンロンは実写風の人物顔・トリビアの沼と1989年生まれの放課後はアイコン自体なし。[02](./02_競合分析.md) 2章）。
声はキャラの同一性（4-2）のまま、見た目は「スレ民・寸劇の登場人物」として役柄で選ぶ。

- 生成はCanvaのAI画像生成（`logo`タイプ・800×800で書き出し）。全員を**同一プロンプトテンプレ**で
  一括生成しないと絵柄が揃わない（#179で1人ずつ作って混在した実敗）。テンプレ:
  「1990年代の日本のセルアニメ風の顔アイコンイラスト。＜役柄・髪・表情の記述＞。
  正面向きのバストアップ構図で顔を中央に大きく。太く均一な主線、フラットなベタ塗り＋影は2段階まで、
  ハイライト控えめ。背景は＜キャラ色＞の単色ベタ塗りで画面の端まで塗りつぶす。文字・ロゴ・枠は入れない」
- 役柄・性別・年齢は声と一致させる（[05](./05_コンテンツ企画.md) チェックリスト）。
  例外は `takehiro_nekketsu` のみ劇画・金太郎風の怒り顔（showaの熱血キャラ。[00](./00_サマリー.md)）
- 生成物はgit管理外（`content/assets/` ごと除外）なので、消えたら上のテンプレで再生成する。
  `.venv/bin/python tools/fetch_icons.py` が全話者ぶん揃っているかを検品する
- credits.txt には「アイコン: AI生成（Canva）」を出す
- 背景色は字幕と同じキャラ色。色＝話者の対応を画面全体で崩さない
- 再生成したら `content/assets/<id>/icon_*.png` のキャッシュも消す（古い顔で焼き直されるため）

### 4-9. 演出はチャンネルごとに変える（v6.1）

**尺・テンポ・効果音・カット頻度は `data/channels/<ch>.json` の `style` が持つ。**
コードの定数はフォールバックにすぎない。

ジャンルごとに勝ち方が違うことが実測で分かったため（[02](./02_競合分析.md) 1章）:

| | `meme` | `showa` | `heisei` |
|---|---|---|---|
| ベンチマーク | ロンロンの天秤 51.2万 | 未実測（[#152](https://github.com/bashaka-sawabe/personal-sns-operation/issues/152)。尺の目標が借り物） | 1989年生まれの放課後 21万回 |
| 話速 | 1.30（速い） | 1.20 | 1.15（ゆったり） |
| フレーズ間 | 0.02秒 | 0.05秒 | 0.09秒 |
| パンチイン | 1.14（強い） | 1.12 | 1.05 |
| 背景 | **0.45秒ごとにカット** | 0.7秒ごとにカット | Ken Burns |
| 背景の系統 | 飯テロ・ASMR（内容と無関係） | 工場・職人・レトロ街並み（時代の空気と一致） | 商品写真（内容と一致） |
| 狙う尺 | 26〜32秒 | 55〜59秒（旧triviaからの借り物） | 2〜4分 |
| `max_chars` | **230** | **364** | **776** |
| 効果音 | 軽い転換音＋ズッコケ | 和太鼓の転換＋種明かし | 和太鼓＋締め |

> `trivia`（ゾウの鼻毛）は 2026-08-08 に廃止（[#192](https://github.com/bashaka-sawabe/personal-sns-operation/issues/192)）。
> 実測値（トリビアの沼 993万回・話速1.18・フレーズ間0.07秒・Ken Burns・55〜59秒）は
> [02](./02_競合分析.md) 1章に残っている。

**背景カット（`cut_interval`）は Ken Burns の代わりに使う。** 拡大率と位置を
不連続に切り替えると「別カットに切り替わった」と目が認識する
（実測: `meme-013` のフレーム差分で 0.47秒ごとのピークとして検出される）。
高刺激の映像を刻むロンロン型のテンポを、素材1枚から近似する仕掛け。

> **2026-08-05まで、これは静止画にしか掛かっていなかった**（[#141](https://github.com/bashaka-sawabe/personal-sns-operation/issues/141)）。
> Pexels映像が取れたシーンでは `cut_interval` が何もしておらず、
> 背景が取れているときほどテンポが死ぬという逆転が起きていた。今は映像にも掛かる。

**尺は行数ではなく字数で縛る**（[#150](https://github.com/bashaka-sawabe/personal-sns-operation/issues/150)）。
行数を決めても1行が伸びれば尺は伸びるため、`max_chars`（セリフの合計字数）が上限になる。

値は**推測ではなく実測から出す**: `字数 ÷ 実際の尺` で字/秒を測り、狙う秒数を掛ける。

| ch | 実測 | 狙う尺 | max_chars |
|---|---|---|---|
| `meme`（speed 1.30） | 224字 / 29.3秒 = 7.65字/秒 | 26〜32秒 | 230 |
| `showa`（speed 1.20） | 453字 / 68.5秒 = 6.61字/秒 | 55〜59秒 | 364 |
| `heisei`（speed 1.28） | 390字 / 60.3秒 = 6.47字/秒 | 2〜4分 | 776 |

> 最初は実測せずに置いたため `showa` が **68.5秒**（ベンチ55〜59秒）になった。
> 話速が違うと字/秒も変わるので、`speed` をいじったら測り直す。

> `style` を書かないチャンネルは従来の共通値で動く（後方互換）。

### 4-10. バッチは1本落ちても止めない

`--batch` は失敗した本をスキップして残りを作り切り、最後にまとめて報告する。
夜間に流して朝に結果を見る運用を前提にしている。

## 6-2. プラットフォームの役割分担

| PF | 投稿 | 役割 |
|---|---|---|
| **YouTube Shorts** | **自動（実装済）** | **ストック**。検索経由で寿命が長く、1本が数ヶ月効き続ける。収益化条件も最も明確 |
| Threads | 自動（未実装・最軽量） | テスト場。テキストで反応を見てから動画化する |
| Instagram Reels | 自動（未実装） | 主戦場。平均年齢37歳で仕事・お金の文脈が刺さる |
| TikTok | サードパーティ経由 | 発見エンジン。0フォロワーでも当たる |

YouTubeだけ性質が違う。IG/TikTokは**フロー**（数日で消える）、YouTubeは**ストック**。
同じ12本でも、YouTubeに置いた分だけが3ヶ月後も効いている状態になるので、
テスト期でも必ず4面すべてに出す。

## 7. 禁止事項（[08](./08_自動化.md) 2章を継承）

自動フォロー・自動いいね・自動DM・フォロワー購入は3PFすべてで規約違反。
**投稿直後30〜60分のコメント返信は手動**。ここは自動化しないほうがアルゴリズム上も有利。
